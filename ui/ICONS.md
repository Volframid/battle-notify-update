# Game icon assets

The archive covers 139,968 buff, item and skill ID mappings with 10,443 distinct PNGs. Mappings use the local Asura client metadata extraction dated 2026-10-28. Textures combine the TeraDpsMeterData collection and read-only extraction from the installed Asura client. Source collection: https://github.com/neowutran/TeraDpsMeterData . See ICON-LICENSE.txt for the collection license. TERA game artwork belongs to its respective owners.

`icons.json` contains the ID index and the original small icon set. Sixteen compressed texture packs in `icon-packs/` extend coverage without inflating every texture into memory. The resolver caches at most four packs. The Toolbox updater installs all packs; no game package modification is required.

Assets are bundled locally; no running meter or external service is required. This covers the five older Ninja rules and the Cyclone stage reset ID. It does not claim that every numeric ID has artwork: 4,518 source rows have no icon name, two common skill IDs have conflicting race-specific metadata, and three named textures are absent from the installed resources. Those textures are `icon_status.electriccharge12_tex`, `icon_status.icon_resonance_common1_tex` and `icon_status.icon_resonance_common2_tex` (14 buff IDs total). The old rule aliases 1004 and 4022 have no direct icon in this source; 4022 is explicitly a hidden effect. Missing artwork retains the notification text and a neutral marker, rather than displaying an unrelated skill.

Maintainers can rebuild using `scripts/build-icons.py` with explicit datacenter, collection ZIP and extracted client PNG paths. The private coverage report must be written outside this module. The build validates every PNG and mapping. Unrecognized missing named textures stop the build so future omissions cannot silently ship. Updating the server's icon metadata requires rebuilding; unknown IDs introduced after the source snapshot are not automatically discovered at runtime.
